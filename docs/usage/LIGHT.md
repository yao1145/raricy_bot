# Raricy Bot Light Windows 桌面版使用手册

本手册面向 Windows x64 桌面用户。Light 以 ZIP 目录形式提供，包含运行时；使用者不需要另装 Python、Node 或 Docker。你仍需准备有聊天权限的站点账号、模型服务地址、模型名称和 API Key。

Light 保留聊天、可选的图片理解、博客评论、本地知识库和长期记忆。Light 不提供 MCP 工具（例如 /search、/zhihu、/map、/wolfram）或定时发文。功能边界和验收状态见[发行版设计](../design/LIGHT_EDITION_DESIGN.md)；站内触发规则及隐私说明见[站内使用指南](USAGE.md)，其中完整版专属命令不适用于 Light。

## 1. 安装与首次设置

1. 取得对应版本的 Light ZIP。若发行包附有 SHA-256 文件，在 PowerShell 中对下载的 ZIP 完整路径执行 `Get-FileHash -LiteralPath '粘贴 ZIP 完整路径' -Algorithm SHA256`，再将结果与发布方给出的值核对。
2. 将 ZIP 解压到本机一个长期使用的目录，并保留解压出来的完整 `RaricyBotLight` 文件夹。不要只复制 EXE，也不要直接从压缩包预览运行。
3. 双击 `RaricyBotLight.exe`。正常情况下不会出现终端窗口；首次启动会打开本机管理页并显示向导。
4. 在第一步填写站点账号和密码并点击「测试站点」。测试会登录并探测聊天权限，不会发送聊天消息；登录成功后会取得站点稳定用户 ID。密码发生变化后需重新测试。已有档案绑定原站点账号，不能在本档案里切换账号。
5. 在第二步填写模型 API 地址、模型名称和 API Key，设置 System Prompt，并点击「测试模型」。测试使用当前未保存的输入值。站点地址首版固定为 `https://raricy.com`；模型端点需兼容 OpenAI Chat Completions，非本机地址须使用 HTTPS。
6. 第三步按需勾选图片理解、博客评论、知识库或长期记忆。首次设置时，先完成站点登录测试并取得稳定用户 ID，才能启用知识库和记忆；该 ID 不同于登录用户名。已有设置恢复时会载入原有名单；更新密码后必须重新测试。图片理解需要模型支持图片。对话和图片内容会发送到你配置的模型服务；博客评论会实际发布并通知被回复者，启用前请先阅读[触发规则](USAGE.md#2-怎么叫我)和[隐私说明](USAGE.md#7-隐私关于你的消息)。

7. 点击「保存并启动」。配置保存成功后才会启动机器人。启动失败时，已保存的设置仍保留，可在设置页修改后重试。管理页只供本机使用，地址绑定 `127.0.0.1`；不要把页面地址、浏览器会话或本机数据目录分享给他人。

### 凭据保存方式

密码与模型 API Key 通过当前 Windows 用户的系统凭据库保存，配置、草稿和运行快照中不包含它们的明文。设置页会显示当前凭据后端及其可用状态。

如果安全凭据后端不可用，Light 会使用仅本次 Controller 运行有效的内存凭据，并在设置页标明。此时退出或重启 Light 后，需要重新填写密码与 API Key；不要把这种状态当作已经持久保存。Light 不会因此改写 `.env` 或创建明文密钥文件。

配置页中的「保持不变」「替换」「删除」分别表示保留当前凭据、提交新值、移除该凭据。替换凭据后保存设置；如机器人正在运行，再重启机器人使其使用新版本。

## 2. 日常启动、启停与退出

| 操作 | 结果 |
|---|---|
| 首次双击已配置的 Light | 启动控制服务；按设置中的启动偏好启动机器人 |
| 控制服务已运行时再次双击 | 打开已有管理页，不创建第二个实例，也不覆盖你手动停止机器人的状态 |
| 关闭浏览器标签页 | 只关闭页面；机器人和控制服务继续运行 |
| 管理页「状态」→「启动」 | 启动已保存配置对应的机器人 |
| 「停止」 | 停止机器人；管理页和控制服务保留 |
| 「重启」 | 停止当前机器人，再用已保存配置启动 |
| 「退出 Light」 | 停止机器人、关闭控制服务；当前管理页会话失效 |

设置页的「打开程序时自动启动机器人」只决定下一次启动 Light 时是否一并启动机器人；它不会让 Light 在 Windows 登录时自动运行。首版没有托盘或自动更新。

状态页会区分机器人进程、配置和各子系统状态。显示「未知」或「已过期」表示当前没有足够新的状态证据；配置修改后，站点或模型测试结果也会过期。不要只凭一个「运行中」状态判断站点、模型、知识库和记忆都正常。

## 3. 设置、连接测试与生效方式

在「设置」页编辑模型地址、模型名称、System Prompt、可选能力和高级运行字段。高级字段包括上下文、队列、并发、超时、评论轮询间隔和日志级别。只改你了解的项；字段校验失败时按页面显示的字段提示修正。

首次设置时可在向导第 1、2 步分别测试站点和模型；两项都临时使用当前表单输入，不保存凭据或配置。保存配置后也可在设置页重测：

- **测试站点**在向导中使用当前输入的账号和密码，登录并探测聊天权限，不发送聊天消息；登录成功时会返回稳定用户 ID。设置页中的测试使用已保存凭据，且必须先停止机器人。登录成功但聊天权限探测失败时，测试仍会失败。
- **测试模型**向模型服务发送一条固定的小型测试请求，检查接口与凭据是否可用；向导中使用当前未保存的 API 地址、模型名和 Key，设置页中使用已保存配置。测试不显示模型生成正文，服务可能计费或扣除额度。
- 设置页的测试针对当前已保存 revision。保存配置或更换凭据后，回到状态页重测；旧结果会标为过期。向导中的测试结果不会被记作已保存配置的测试结果。测试通过只证明该次请求成功，不保证之后网络、服务和额度一直可用。

设置保存后不会热更新正在运行的机器人。若要让改动生效，在状态页选择「重启」；也可以先「停止」，再「启动」。设置页仅在首次配置时可填写站点账号；之后账号名固定在当前档案里。密码可以更新，保存新密码后须重新测试站点。Light 首版没有自助切换账号或迁移数据的流程；需要换账号时先退出并联系维护者安排独立档案，勿将另一个账号的凭据写进现有档案。也不要在完整版和 Light 中同时运行同一个站点账号。

## 4. 知识库与长期记忆

### 本地知识库

知识库是你导入的 Markdown 资料，不会自动联网搜索。首次设置可勾选「本地知识库」；之后在设置页开启能力、填写使用范围并导入资料。

1. 在知识库访问字段里选择频道与允许的稳定用户 ID。建议先只开放必要的私聊用户；若开放大区会话，机器人仍只在站点规定的精确 @/回复触发条件满足时响应。
2. 在「知识库导入」区域填写 `.md` 文件名，并将 Markdown 正文粘贴到内容框后点击「导入」。每次导入一份，单文件上限为 1 MiB；不接受目录路径或压缩包。再次导入同名文件会替换该文件。
3. 状态页会显示加载到的资料数量和片段数。新资料可能要等知识库刷新后才可检索；用 `/kb <问题>` 在允许的对话中检索。没有命中时机器人会说明没有相关资料，不会伪装成知识库已回答。

权限列表使用站点测试返回的**稳定用户 ID**，不是显示用户名或登录账号。首次向导会把当前测试账号 ID 预填为本人范围；恢复向导时会保留原有有效名单。更新密码后先重新测试，再使用知识库或记忆；现有档案不能切换站点账号，勿将另一个账号凭据写入此档案。新增其他使用者时到设置页调整名单。`allowlist` 只允许名单中的用户；`all_chat` 会把能力开放到所选频道中的会话。导入前请清理文件内容：命中的资料片段会随问题发送给你配置的第三方模型服务；不要导入密码、Cookie、个人隐私或无权转交模型的内容。

### 长期记忆

首次向导会将站点测试返回的稳定 ID 预填到记忆允许名单和管理员名单；恢复时保留原有名单。更新密码后先重新测试；当前档案不能换绑到另一个站点账号。需要授权其他用户或调整管理员时，在设置页分别编辑两份名单。管理员名单与使用者名单含义不同；按界面校验，管理员也必须在允许名单内。记忆命令只在私聊中使用；启用能力不等于每个站点用户都自动获准访问，也不会取消用户自身的记忆开关和授权。

用户可使用 `/remember <内容>` 明确保存记忆；用 `/memory status` 查看开关与条目数，用 `/memory on` 或 `/memory off` 控制是否在自己的私聊回复中参考私有记忆，用 `/memory list` 查看自己的条目，用 `/memory forget <UM-ID>` 删除一条，用 `/memory clear` 清空私有记忆。若部署策略允许，可用 `/memory auto on` 或 `/memory auto off` 控制自动记忆提取；该开关与私聊中是否参考记忆分开。共同记忆的提议与审核仅供配置好的管理员使用。`/reset` 只重置短对话，不删除长期记忆。

记忆保存在本机档案目录。被用于整理或回复的记忆内容也可能随相关请求发送给模型服务；公开记忆还可能进入公开会话的模型请求。不要记入密码、API Key、验证码或不希望交给模型处理的内容。Light 设置页没有自动记忆采集的开关；不要把私聊内容会被自动保存当成默认行为。更多命令语义见[站内使用指南的长期记忆说明](USAGE.md#3-命令手册)。

## 5. 数据位置与备份

Light 的用户数据根目录为：

`%LOCALAPPDATA%\RaricyBotLight`

在文件资源管理器地址栏输入该路径即可打开。常见内容如下：

| 路径 | 内容 |
|---|---|
| `diagnostics\launcher.log` 与滚动备份 | Launcher 启动、激活与控制服务诊断；单文件有界并保留一个滚动备份 |
| `runtime\` | 当前实例元数据 |
| `profiles\<档案 ID>\config.yaml`、`draft.yaml`、`revisions\` | 非敏感配置、草稿与配置版本；不应手工编辑 |
| `profiles\<档案 ID>\data\` | SQLite 数据及长期记忆 |
| `profiles\<档案 ID>\knowledge\` | 导入的 Markdown 知识库 |
| `profiles\<档案 ID>\logs\runtime\` | 机器人运行日志 |
| `profiles\<档案 ID>\logs\errors\` | 可选的永久错误归档；启用后不会随普通日志轮转或配置回退自动删除 |

备份或迁移前，先在管理页点击「退出 Light」，等待程序完全退出；再复制整个 `RaricyBotLight` 数据根目录。不要只复制 `bot.db`：SQLite 可能还有 `-wal` / `-shm` 文件，知识库和记忆也在其他子目录。运行期间复制可能得到不一致的数据库备份。

备份不包含 Windows 系统凭据库中的实际密码和 API Key。恢复到另一台电脑或另一个 Windows 用户后，在设置页重新填写凭据并保存。保护备份与保护记忆文件一样重要。

## 6. 诊断与常见问题

先查看管理页「近期事件」，再查看 `%LOCALAPPDATA%\RaricyBotLight\diagnostics\launcher.log`。近期事件最多显示 200 条，控制服务重启后列表会重新开始。诊断使用固定事件码和白名单字段，不记录聊天正文、System Prompt、Cookie 或凭据；如需把文件交给维护者，仍先检查其中是否含有你不希望分享的本机标识。

| 现象 | 建议处理 |
|---|---|
| 双击后看不到页面 | 稍等数秒再试一次；再次双击会激活已有实例。若仍无页面，检查 `diagnostics\launcher.log`，并确认数据目录可写、没有被安全软件拦截。 |
| 页面显示会话失效 | 当前浏览器会话只在控制服务运行期间有效。重新双击 Light 打开管理页。 |
| 配置显示需要重新填写凭据 | 检查设置页显示的凭据后端。若为内存模式，填入站点密码和模型 Key 后保存。 |
| 向导测试了新账号但保存被拒绝 | 已有档案绑定原站点账号，换账号不属于当前设置流程；保留旧档案数据，联系维护者安排单独的新档案。 |
| 站点测试失败 | 先停止机器人再测试；核对站点密码，并确认账号有聊天权限、网络可访问站点。测试错误仅显示固定类别，不会显示密码。 |
| 模型测试失败 | 核对兼容 API 地址、模型名称、Key 和网络；非本机地址使用 HTTPS。检查模型服务额度与服务状态。 |
| 设置已保存但机器人还用旧值 | 在状态页重启机器人。保存不会热更新运行中的配置。 |
| 状态页显示知识库未就绪或 /kb 无结果 | 检查知识库是否启用、ID/频道权限是否正确、Markdown 是否导入成功；等待刷新后再试。 |
| 机器人没有回复 | 检查站点的触发条件、状态页的站点与模型状态、近期事件及账号额度。Light 不支持 MCP 工具命令。 |

不要通过手工改写 YAML、数据库或运行元数据来排障。需要重置配置、迁移档案或修复损坏数据时，先保留完整停机备份，再联系维护者。

## 7. 升级、回退与卸载

### 手动升级

1. 在管理页选择「退出 Light」，等待进程完全退出。
2. 复制一份完整数据根目录作为停机备份；同时保留当前应用目录，方便诊断。
3. 将新版本解压到应用目录。升级前先保留旧目录；不要只覆盖单个 EXE 或 DLL。
4. 启动新版本，检查配置状态、机器人状态、知识库数量和记忆功能。

首版没有自动更新。若升级后数据 schema 已变化，旧程序可能不能读取新数据；回退前先确认兼容性。无法确认时，使用升级前的停机备份恢复整份数据目录，再启动旧版本。配置版本回退不会撤销已发送的消息、评论或其他站点操作。

### 卸载与彻底删除

- 普通卸载：先退出 Light，再删除应用程序目录。用户数据与系统凭据默认保留。
- 彻底清理：退出 Light 后删除 `%LOCALAPPDATA%\RaricyBotLight`，并打开 Windows「凭据管理器」，删除由 `RaricyBotLight` 服务保存的条目。删除前确认已备份想保留的知识库、记忆和数据库。

## 8. 已知限制与发行验收状态

- 当前发行目标是 Windows x64。没有在其他平台完成发行验收。
- §17.2 的**干净 Windows 验收尚未完成**：当前记录只有开发机 Windows 11 x64 上的冻结程序冒烟，没有在一台未安装 Python、Node、Docker 的独立 Windows 环境完成整套用户流程。
- **真实站点与真实模型验收尚未完成**。自动化验证使用替身，不代表真实账号登录、权限、第三方模型服务或额度已验收。
- 冒烟工具 `tools/smoke_light.py` 只覆盖冻结程序的启动、激活、本机会话、状态页、凭据后端和退出等发行基础；它不启动真实机器人，也不访问站点或模型。
- 仓库的 `tests/` 目录按 `.gitignore` 规则被忽略。本机存在的测试不会随普通 Git 克隆自动提供；发行/CI 验证需要明确提供相应测试文件，不能把干净克隆中「未发现测试」当作测试通过。
- 向导的「保存草稿」会恢复非敏感设置字段（如模型地址、模型名、能力选项和权限名单）；密码、模型 API Key、站点账号名与 System Prompt 不写进草稿。首次设置恢复时请重新填写账号、密码和 API Key；System Prompt 会取已保存值或默认模板。
- 管理页只监听本机回环地址，不用于局域网或公网管理；首版没有托盘、Windows 登录自启动、自动更新或多账号并行控制台。
- 电脑关机、睡眠或断网时机器人无法继续工作。需要持续在线运行时，请评估[完整版服务器部署手册](DEPLOYMENT.md)。

L5 设计验收清单见[发行版设计 §17](../design/LIGHT_EDITION_DESIGN.md#17-验证与发行验收)。
