# Raricy Bot Light 使用与部署

面向桌面用户的独立发行版：自带运行时、无需 Python/Node/Docker，首次配置在浏览器里完成。
设计依据见 [LIGHT_EDITION_DESIGN.md](../design/LIGHT_EDITION_DESIGN.md)；完整版（服务器/Docker）
的部署见 [DEPLOYMENT.md](DEPLOYMENT.md)，两者共用同一份核心代码但**不得装进同一个 Python 环境**。

适用范围：**Windows 桌面 x64**。其他平台只有抽象边界，尚未做发行验收。

## 1. 安装与首次启动

1. 解压发行 ZIP 到任意目录（中文与空格路径都可以）。
2. 双击 `RaricyBotLight.exe`。没有终端窗口是正常的：程序在后台启动控制服务。
3. 首次启动会打开管理页并停在向导：填站点账号与密码、模型 API 地址与模型名称、模型 API Key，
   确认 System Prompt，选择需要的可选能力（图片理解、评论、知识库、长期记忆）。
4. 点「保存并启动」。配置先提交（写进本机数据目录），再启动机器人；启动失败也会保留已保存的配置。

「即开即用」指运行时随包提供、首次配置可在界面完成；站点账号、模型服务、网络与额度仍由你自己提供，
发行包不内置任何共享 Key。

## 2. 日常使用

| 你要做的事 | 怎么做 |
|---|---|
| 再次打开管理页 | 再双击一次 `RaricyBotLight.exe`：它检测到已有实例，只打开页面，不会起第二个机器人 |
| 关闭浏览器 | 什么都不用做：控制服务与机器人在后台继续运行 |
| 停止 / 重启机器人 | 管理页「状态」页的按钮；重启会用已保存的配置 |
| 改配置 | 管理页「设置」页；保存后按提示重启才会生效（运行中的实例不会热更新） |
| 退出 Light | 管理页「退出 Light」：先停机器人，再关控制服务并让页面会话失效 |
| 看发生了什么 | 管理页「近期事件」：只有固定事件码与白名单字段，不含正文与凭据 |

## 3. 数据、日志与凭据位置

数据根：`%LOCALAPPDATA%\RaricyBotLight`

```text
launcher.json            活动档案指针
diagnostics/             有界诊断日志（launcher.log，自动轮转）
runtime/                 实例元数据（不是锁）
profiles/<档案 id>/
  config.yaml            非敏感配置与一个不透明的凭据引用
  draft.yaml             向导草稿（同样只有非敏感字段）
  revisions/             回退快照（每次提交一份）
  runtime/               按版本生成的运行快照（Worker 用它启动）
  data/                  bot.db（含 -wal/-shm）与 memory/
  knowledge/             受管 Markdown 资料
  logs/runtime/          有界运行日志
  logs/errors/           永久错误归档（默认关闭；开启后只增不删）
```

- **密码与模型 Key 只存在于系统凭据库**（Windows 凭据管理器，服务名 `RaricyBotLight`），
  配置文件、草稿与快照里都只有一个随机引用。系统凭据库不可用时程序会改用**仅本次运行**的
  内存模式并在界面上说明：重启后需要重新填写，不会把密钥写进明文文件。
- 同一个数据目录**同一时刻只允许一个写者**：完整版 CLI 与 Light 共用这把锁。第二个进程会以
  退出码 4 结束，不会去动数据。

## 4. 升级

1. 先在管理页「退出 Light」。
2. 备份数据根（它包含记忆与知识库；凭据在系统凭据库里，**不随备份迁移**）。
3. 用新版本覆盖应用目录，再双击启动。
4. 启动时会检查配置与 schema 版本；不兼容时程序会停下并显示原因，不会把旧配置重置成默认值。

回退版本前先确认新版本没有改过数据库 schema；必要时恢复停机时的备份。

## 5. 卸载与清理

- 删除应用目录即可卸载程序；**数据与凭据默认保留**。
- 彻底清理：退出 Light 后删除 `%LOCALAPPDATA%\RaricyBotLight`，并在「凭据管理器 → Windows 凭据」
  里删除 `RaricyBotLight` 下的条目。永久错误归档若已启用，也在数据目录里，删除前请自行留存。

## 6. 故障排查

| 现象 | 处理 |
|---|---|
| 双击没反应、页面打不开 | 看 `diagnostics/launcher.log`；确认没有另一个进程占用同一数据目录（退出码 4） |
| 页面提示「会话已失效」 | 会话只在当前控制服务运行期间有效；从桌面图标重新打开管理页即可 |
| 启动失败（状态页显示故障） | 「近期事件」里的事件码与退出原因给出分类；配置问题按字段提示修改后重启 |
| 站点测试失败 | 登录成功不等于可聊天：测试会另外探测聊天权限；失败原因以固定类别码显示 |
| 模型测试失败 | 只回固定类别码（超时、限流、不支持等），不会显示模型输出内容 |

## 7. 已知限制与尚未完成的验收

- **干净 Windows 验收（§17.2）未执行**：本机开发环境下的冻结产物冒烟通过，但没有在「没有
  Python/Node/Docker」的独立机器上跑完整清单。
- **真实站点与真实模型验收未执行**：全部自动化测试使用替身，不连接站点或模型服务。
- 首版没有托盘、没有登录自启动、没有自动更新；升级是手动替换应用目录。
- 管理页只监听 `127.0.0.1`，仅供本机使用；不要尝试把它暴露到局域网或公网。
