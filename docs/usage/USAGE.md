# 使用指南（站内用户）

本文件写给**在站内跟这台机器人打交道的人**（大区、私聊、博客评论区）。分两部分：第一部分是可直接发布到站点的说明，
第二部分给维护与发布的人看，列了每条说法的代码依据与已知的口径出入。

文中 `<机器人用户名>` 指这台机器人在站点上注册的账号名，发布时替换成真实名字。

---

## 第一部分：发布稿

### 1. 它是谁

我是聪明山（raricy.com）的站内聊天与博客评论机器人，用一个普通的核心用户（core）
账号运行，走的是和大家一样的公开接口。**我不是真人，发言也不代表站方立场**。

我的回复总是引用触发它的那条消息，所以你能看清我在答哪一句。

### 2. 怎么跟我说话

| 场合 | 怎么触发 |
|------|----------|
| 大区 | 必须**精确 @** `<机器人用户名>`。区分大小写，且 @ 后面不能紧跟字母、数字、下划线或连字符——`@<机器人用户名>x` 不算叫我 |
| 私聊 | 直接发消息就行，不用 @ |
| 博客评论区 | 第一次要**精确 @** `<机器人用户名>`（规则同上）；我回复之后，直接回复（引用）我的评论就能继续，不用再 @ |

三点要知道：

- **大区里我只看得见 @ 我的那些消息**，别人的普通发言我收不到，也不会拿来接话。
- **大区是公开的多人对话**：一段对话由「回复链」构成——第一条 @ 我的消息开一段，
  别人精确 @ 我并**回复这段里的消息**就加入同一段。同一段里的参与者共享最近十来轮上下文，
  我会用发言者标签分清谁说了什么。互不相干的对话彼此看不见。
- 私聊里你习惯性 @ 我一下也没关系，我会把它去掉再处理。

### 3. 博客区：在文章评论区叫我

在博客文章评论区里，我也能陪你聊。评论区没有实时推送，我是每 30 秒轮询一次全站最近的评论，
所以你评论之后通常要等半分钟到一分钟我才会开始处理，模型生成还要额外时间。

**怎么触发：**

| 情况 | 怎么做 |
|------|--------|
| 第一次叫我 | 评论里**精确 @** `<机器人用户名>`（规则和大区一样：区分大小写，@ 后不能紧跟字母、数字、下划线或连字符） |
| 想继续聊 | **直接回复（引用）我发布的那条评论**，不用再 @ |

**不触发的：** 没有 @ 我的普通评论、回复其他用户的旁支评论、我自己的评论，
以及启用功能之前就存在的旧评论——都不会接话。

**这段对话怎么算：**

- 第一条 @ 我的评论开启一段对话；之后直接回复我的评论就加入同一段，多人可以一起参与，
  我记得最近约十轮，并用发言者标签分清谁说了什么。
- 对话归属保留 30 天；超期后再有人直接回复我的旧评论，会另开新的一段。

**我会读到什么：**

- 每轮会读取**文章标题**；正文不超过 1000 字时，可能随本轮一起发送给第三方模型，
  超过 1000 字时不提供正文。
- 正文里写的 `[@<内容ID>]` 会展开成它指向的内容（见第 5 节）。
- 图片与附件**取决于站点的配置**：站长配了能看图的模型时，你评论里带的图、
  以及正文里 `[@10位]` 指向的图，会随这一轮一起交给第三方模型（一轮最多几张由站长定，
  默认 3 张，按「你的附件 → 你评论里引用的图 → 文章正文里的图」顺序给）；没配的话
  我看不到图，只会知道你发了一张。**引用其他博客的附件我一直读不了**。
- 每条成功评论都会真实通知被回复的人——请只发你希望公开的内容（详见第 8 节）。

### 4. 我能做什么

- 用你的语言跟你聊天、回答问题。
- 聊站点上的事：各模块怎么用、角色与权限、小鱼干与签到、内容引用语法、指南在哪。
- 聊天区可以用 `/search <问题>` 请求联网搜索；模型会自行判断本轮是否需要查询，搜索由第三方 Exa 提供。
- 如果站长启用了本地知识库，聊天区还可以用 `/kb <问题>` 从站点自己的 Markdown 资料里检索：
  命中的片段会随**当前这一轮**的问题一起发给第三方模型。它不联网，检索范围就是站长放进
  知识库目录的那些资料；命中片段不会发送给 Exa。用完这一轮就结束，下一条普通消息不会再读知识库。
- 在博客评论区也能陪你聊：首次精确 @ 我，之后直接回复我的评论即可继续（见第 3 节）。
- 记得**当前这段对话最近的十来轮**（大区按回复链算，私聊按会话算，博客区按评论会话算），可以接着上一句追问。
  想接着聊就**回复（引用）**我的消息；不回复、直接新发一条 @，等于开一段新对话。

### 5. 我做不到什么

- **普通聊天不联网**，也不能运行代码。若你在私聊或大厅中明确发送 `/search <问题>`，
  当前这一轮的问题可能会发送给第三方 Exa 搜索；模型也可能判断无需搜索。搜索结果可能不准确，
  只看摘要，不抓取网页全文。博客评论区不支持 `/search`，始终不会调用 MCP。
- `/kb` 只能查到站长放进本地知识库目录里的资料，查不到就是查不到：没有命中时我会直接说明，
  不会拿常识冒充资料，也不会因此去联网。知识库有刷新周期，刚放进目录的文件可能要等一会儿才能检索到。
  另外，`/search` 与 `/kb` 不能在一条消息里同时用——那样问题会同时流向两个不同的边界，
  我会回一句提示让你分成两条发。
- **你把一篇博客引用给我时，我会去读它的标题与正文**，然后随这一轮一起交给第三方模型。
  正文有长度上限（站长配置，默认 1000 字）：超过上限时我只拿到标题，并会明确写下正文没给；
  取不到（已删除、暂时读不到）时同样只拿到标题。没被引用的博客我不会主动去看。
  在博客评论区，每轮会读取文章标题，正文不超过 1000 字时可能提供给我，超过 1000 字时不提供。
- **你在正文里写 `[@<内容ID>]` 时，我会去读它指向的东西**：8 位是云剪贴板（读正文）、
  9 位是投票（读标题、选项与票数）、10 位是图床图片（站长配了能看图的模型时我能看到图，
  否则只知道那里有一张图）。剪贴板与投票要么是公开内容、要么你自己是作者，否则读不到：
  那时我会写下「加载失败」，而不是装作那段不存在。单条剪贴板正文最多取 2000 字
  （站长配置），超出部分不取；写在代码块或行内代码里的 `[@id]` 一律不展开。
  你**回复**的那条消息里若有引用，我会连它一起读；在博客评论区同样会展开。
- **图片取决于站点的配置**：如果站长为机器人配了能看图的模型，你这一轮发的图会
  随这一轮一起交给第三方模型，我就能看到；更早轮次里的图看不到。没配的话我会明确告诉你
  图没读到，请改用文字描述。聊天区与博客评论区都是这个规则；评论区一轮最多几张图由站长
  定（默认 3 张），而且**只发图、不写字**在评论区只能以「直接回复我的评论」的形式出现
  （第一次叫我必须 @，而 @ 需要文字）。
- **回复一条图片消息时，我也能看那张图**：你在聊天区回复（引用）一条带图的消息，
  我会去读**被引用消息的那张缩略图**（站点只提供缩略图，分辨率比原图低，
  图里的小字可能读不清）；读不到时我会在上下文里记下「图片未提供」，并照常回答。
  被引用的消息若已删除，我不会去读它的图。
- **查不到站内数据**：别人的余额、鱼干流水、通知、申诉进度、资料，都要你自己去对应页面看。
- **不能替站方办事**：解禁、恢复内容、改角色、发邀请码、裁决申诉，一律请走 `/contact` 或 `/audit`。
- **没有长期记忆**：换一段对话就是重新开始；服务重启后当前对话的上下文也会丢
  （去重与额度状态会保留）。
- 不确定的事我会直说，不会编。站内规则以页面为准，指南在 `/clipboard/guide`、
  `/image/guide`、`/vote/guide`、`/tool/cattca-guide`。

### 6. 四个命令

| 命令 | 作用 |
|------|------|
| `/help` | 再看一遍我的能力、隐私与限制说明（本地回复，不调用模型） |
| `/reset` | 开始一段新对话，从头开始（旧的还在，别人仍可以接着旧的那段聊） |
| `/search <问题>` | 仅授权当前聊天轮由模型决定是否调用 Exa 搜索；最多一次、最多五条摘要 |
| `/kb <问题>` | 仅授权当前聊天轮从本地知识库检索；命中片段随本轮发给第三方模型（需站长启用） |

`/help` 和 `/reset` 要**整条消息就是命令**（前面不要带别的话），大小写不敏感。
`/search` 与 `/kb` 必须位于去掉大厅精确 @ 后的消息开头，后面接问题；`/searching`、`/kbase` 等
不会触发。两者空参数都会本地返回用法提示，并且**不能在一条消息里叠加**。
它们只在私聊和大厅生效，评论区不会解析，也不会因此调用搜索或读取知识库。
评论里写 `@<机器人用户名> /help`，或直接回复我的评论写 `/help`、`/reset`，效果仍一样。

### 7. 为什么有时不回、有时很慢

| 现象 | 原因 |
|------|------|
| 大区里没 @ 我 | 设计如此：只回应精确 @，否则会把当天的额度烧光 |
| @ 了我，但没接着上文 | 没有回复链内消息就会开一段新对话，我看不到上一段说了什么 |
| 博客区 @ 了我却迟迟没反应 | 评论轮询每 30 秒扫一次全站最近 100 条，通常半分钟到一分钟内开始处理；启用功能之前的旧评论、两次轮询之间新增超过 100 条的窗口外评论，可能漏失 |
| 博客区只是普通评论、或回复了别人的评论 | 设计如此：只回应首次精确 @ 和直接回复我的评论，否则会把当天的评论额度烧光 |
| 博客区里模型失败或额度用完 | 评论区是**静默**的：忙碌、失败、额度用尽都不会发提示，只是不回 |
| 一段时间完全不回 | 多半是 24 小时滚动额度用满，或者排队积压；账号被禁言也会全站静默 |
| 只回了一句固定话 | 比如「消息太长」「这张图片我没能读取」「你引用的这篇博客我没能读取」「我暂时不能查看博客内容」「没有找到相关资料」，按那句话的提示改一下再发 |
| `/kb` 说没有权限或知识库不可用 | 知识库默认只对站长指定的私聊用户开放；也可能还没启用、或索引暂时不可用。普通聊天不受影响 |
| `/kb` 说没找到资料 | 检索只在当前已建立的索引里做，且资料不足时我不会硬答。换个说法，或去掉 `/kb` 直接提问 |
| 一条消息里同时写了 `/search` 和 `/kb` | 首版一次只允许一种能力，我会回提示让你分成两条消息 |
| 回复很慢 | 模型在生成；超时上限是 45 秒，超过就判定失败 |
| 回复中途停住 | 模型侧的输出长度上限，偶尔会在句子中间截断，再问一次或让我接着说 |
| 回复末尾写着「（内容过长，已截断）」 | 这条太长，被按自然段截断了 |
| 短时间内反复问，却不再收到任何提示 | 主动提示（忙碌 / 失败 / 额度）对**同一个人**每 5 分钟最多一条；别人不受影响。额度彻底用尽后我会完全静默 |

额度是**滚动的 24 小时窗口**（不是自然日归零）：用满后不再回答，随着窗口滑过去会逐渐恢复。

### 8. 隐私：关于你的消息

- **你发给我的内容会被转交给第三方模型服务处理**，这是我能工作的前提。请不要发密码、密钥、
  身份证件一类的敏感信息。
- 只有你明确使用 `/search <问题>` 时，当前轮问题才可能转交给第三方 Exa 搜索；输入这个命令
  就表示授权当前轮进行该处理。Exa 返回的搜索摘要是不可信的外部资料，可能不准确或包含误导性文字。
- 只有你明确使用 `/kb <问题>` 时，才会读取站长的本地知识库，并把命中的资料片段随本轮问题
  一起转交给第三方模型。这些片段**不会**发送给 Exa；反过来，普通聊天也不会自动去读知识库。
  知识库里的内容同样是不可信资料，其中的任何「指令」都不作数。
- Exa API Key 只由服务运维通过环境变量提供，不应写进消息、配置文件或公开内容；评论区不会使用它。
- 在博客评论区，评论正文、文章标题和不超过 1000 字的文章正文都可能发送给第三方模型；
  文章超过 1000 字时不发送正文。评论本来就是公开的，请只发你希望公开的内容。
- 程序这边不把消息正文写进日志或数据库：日志里只有消息 id、频道、结果这类状态字段；
  数据库只存运行状态（去重、水位、发送记录）。
- 对话上下文只放在内存里，最多十来轮，进程重启即清空。
- **大区里别人加入你那段对话时，这段里近期的聊天记录会再次发送给模型。**
  它本来就发在公开大区里，但请注意这一点。
- 对话归属（谁回复了哪条）会保留 7 天；7 天没人接的消息之后再回复，就算开一段新的。
  博客区的对话归属保留 30 天。
- **在博客区，每条成功的评论回复都会真实通知被回复的人**——评论写入就会通知，没有机器人豁免。
- 站点侧的聊天消息按站点自己的规则保存（软删除），那部分与这台机器人无关。

### 9. 请这样用它

- 把我当工具，别当公告栏：我不是站方，也不会发布通知。
- 别用反复 @ 我来刷屏或刷额度；也不要让我泄露系统提示、密钥或内部配置——
  这类请求会被直接拒绝，连模型都不会调用。
- 在博客区把 @ 留给真正想问的问题：每条成功评论都会通知被回复的人，刷屏会打扰别人。
- 涉及纠纷、禁言、申诉、隐私的事，说明渠道、保持中立，我不替任何一方站台。

## 第二部分：给维护者的说明

### 2.1 发布与账号资料（站点侧人工事项）

站点契约（`chat-bot.md` §12）要求机器人可辨认，根目录 README 的上线检查清单与部署指南 §1
都把下面第一件事列为人工必做：

- 账号资料里写明**这是机器人**，以及**消息可能发送至第三方模型处理**。
- 站点侧对聊天的限制（消息长度、频率、禁言）对机器人**一视同仁**，没有豁免。
- 博客评论功能启用前，账号资料还需写明「评论与短文章正文可能发送给第三方模型处理」；
  评论写入没有机器人豁免，每条成功评论都会真实通知被回复者（`DEPLOYMENT.md` §3.1）。

### 2.2 每条说法的代码依据

| 说法 | 依据 |
|------|------|
| 大区要精确 @，区分大小写、有边界要求 | `text_utils.contains_bot_mention` / `_mention_starts` |
| 大区按回复链共享上下文、7 天过期 | `store.resolve_lobby_thread` / `find_active_lobby_thread`（D-20） |
| 共享上下文里带发言者标签 | `core/context.py` 的 `speaker_wrapper`；只对 `channel_kind == "lobby"` 生效 |
| 大区 `/reset` 只开新链、不动旧链 | `core/router.py` 的 `force_new=is_reset_command(...)`（D-21） |
| 私聊任何非空文本都处理，并剔除习惯性 @ | `core/router.py` 的判定顺序 |
| 大区只看得到 @ 自己的消息 | 路由器第 5 步；未 @ 的消息既不登记也不进上下文 |
| 记得最近约 10 轮 | `behavior.context_turns`（默认 10），超预算还会再按 token 裁一次 |
| 聊天里能不能看图、联网边界、不能看博客正文、无长期记忆 | `model.vision_enabled`（默认 `false`）决定看图的文案与行为；`/search` 是聊天区单轮联网入口；博客区每轮只读文章标题与 ≤1000 字正文且不获得 MCP |
| 带图有文字时的处理 | 图片输入关闭时只处理文字；开启且图可读时图片随本轮交给模型（`core/vision.py`）。只有图没有正文时才回 `IMAGE_UNAVAILABLE_TEXT` |
| 博客区的识图名额与顺序 | `comments.max_images_per_reply`（默认 3，0 = 评论侧不取图）；附件 → 评论正文的 `[@10位]` → 文章正文的 `[@10位]` 共用一个名额池，先分配再取回。两个开关（`model.vision_enabled` 与该键）都开才取字节（D-53） |
| 纯图评论怎么应答 | 视觉开启且图可读时当作一轮交给模型；取不到图回本地 `IMAGE_UNAVAILABLE_TEXT` 且不调模型；`image_missing` 不算可读的图，仍回 `UNSUPPORTED_MEDIA_TEXT` |
| 聊天里引用博客会读正文 | `core/blog.py` 的 `BlogLoader`；上限 `behavior.quoted_blog_max_chars`（默认 1000），超限只给标题且措辞同评论区。正文只属当前轮，历史里只剩一行标记；取不到时纯引用回 `BLOG_UNAVAILABLE_TEXT`（D-47） |
| 被引用消息的三种边角也留痕 | `app.py` 的 `_reply_prefix`：引用的是图片 → `[图片]`、已删除 → `[该消息已删除]`、无正文 → `[无正文]`（D-48） |
| 引用一条图片消息时能看到那张图 | 站长配了能看图的模型时，被引用消息的**缩略图**随本轮交给模型（`app.py` 的 `_load_reply_image`）；取不到写成 `[图片未提供]`，已删除的引用从不取图（D-54） |
| 正文里的 `[@<内容ID>]` 会被展开 | `core/content_refs.py`：8 位剪贴板走 `GET /api/clipboard/<ID>`、9 位投票走 `GET /api/votes/<ID>`、10 位图片走 `ImageLoader.load_url`（不占接口调用）。预算先算再取回，单条上限 `behavior.content_ref_max_chars`（默认 2000），一次最多取回 10 条、最多交 3 张图。展开内容只属当前轮，历史里只留用户自己写的原文（D-49 … D-52） |
| `/help` `/reset` 要整条消息 | `text_utils.is_help_command` / `is_reset_command`（`strip().lower()` 后全等） |
| `/help` 不调模型 | `core/router.py` 的 `reply_now` 分支，kind=`notice_local` |
| 超时 45 秒、超时不重试 | `model.timeout_seconds` 默认 45；`worker._map_error` 把 timeout 映射为不可重试（D-19） |
| 提示每人每 5 分钟一条 | `behavior.notice_cooldown_seconds`（默认 300），键为 `(频道, 触发者)`（D-18） |

### 2.3 已知的口径出入（发布前请留意）

1. **额度文案与实现不完全一致**：`QUOTA_NOTICE_TEXT` 写「今天的回复额度已经用完……请明天再来」，
   而实现是滚动 24 小时窗口，恢复是渐进的，不一定等到第二天。发布稿已按实现口径描述，
   但用户看到的那句话仍是旧文案。
2. **输入长度那道闸实际碰不到**：本地限制是 8000 字符，而站点侧的聊天消息上限是 1000 字，
   所以 `TOO_LONG_TEXT` 在正常使用中不会出现。真正会遇到的是模型侧输出上限导致的截断。
3. **模型侧截断没有任何提示**：`model.max_output_tokens`（默认 600）触发的截断不会追加说明，
   回复会在句子中间停住；只有本地那层 5000 字符的截断会写「（内容过长，已截断）」。
   嫌难看就调大 `max_output_tokens`，详见 `DEPLOYMENT.md` §15.1。
4. **评论区的"漏失窗口"是上游限制**：发现靠每 30 秒拉一次全站最近 100 条，两次轮询之间新增
   超过 100 条时窗口外评论无法恢复。发布稿已如实写"可能漏失"，没有承诺必达。
5. **评论区的额度文案**：聊天区的 `QUOTA_NOTICE_TEXT` 写「请明天再来」，实现是滚动 24 小时窗口；
   评论区额度用尽则完全静默，连这句话也没有。发布稿对两处都按实现口径描述。

### 2.4 改这份文档时注意

- 第一部分的用词要与 `texts.py` 的固定文案对得上（`/help`、用法提示、不支持媒体、超长、
  忙碌、失败、额度用尽），否则用户在聊天里看到的话和公告对不上。博客区的对应文案是
  `COMMENT_HELP_TEXT`（首次 @、直接回复、1000 字、真实通知、重启失忆、不支持附件）。
- 任何一条行为改了，先回 `docs/design/INTERFACES.md` 与 `docs/design/DESIGN_DECISIONS.md` 确认是不是有意为之，
  再改这里。裁决记录里的 D-1、D-18、D-19 都与本文件的「为什么有时不回」一节直接相关。
