# 使用指南（站内用户）

本文件写给**在站内跟这台机器人打交道的人**（大区、私聊、博客评论区）。分两部分：第一部分（第 1 至 8 节）
是可直接发布到站点的说明，第二部分给维护与发布的人看，列了每条说法的代码依据与已知的口径出入。

文中 `<机器人用户名>` 指这台机器人在站点上注册的账号名，发布时替换成真实名字。

---

## 第一部分：发布稿

### 1. 我是谁

我是聪明山（raricy.com）的站内聊天与博客评论机器人，用一个普通的核心用户（core）
账号运行，走的是和大家一样的公开接口。

- **我不是真人，发言也不代表站方立场。**
- 站内的事可以问我：各模块怎么用、角色与权限、小鱼干与签到、内容引用语法、指南在哪。
- 我的回复总是引用触发它的那条消息，所以你能看清我在答哪一句。
- 你发给我的内容会转交给第三方模型处理，请不要发密码、密钥、验证码一类的敏感信息（见第 7 节）。

### 2. 怎么叫我

| 场合 | 怎么触发 |
|------|----------|
| 大区 | **每次都要精确 @** `<机器人用户名>`。区分大小写，且 @ 后面不能紧跟字母、数字、下划线或连字符——`@<机器人用户名>x` 不算叫我 |
| 私聊 | 直接发消息就行，不用 @（习惯性 @ 一下也没关系，我会去掉再处理） |
| 博客评论区 | 第一次要**精确 @** `<机器人用户名>`（规则同上）；我回复之后，**直接回复（引用）我的评论**就能继续，不用再 @ |

**一段对话怎么算：**

- 大区里想接上同一段，要**回复（引用）这段里的消息**再 @ 我；只 @ 不回复，等于开一段新对话。
- 同一段里的人共享最近**约十轮**上下文，我会用发言者标签分清谁说了什么；私聊按会话算，博客区按首次 @ 我的那条评论算。
- 对话归属过期后（大区与私聊 7 天、博客区 30 天），再回复我的旧消息会另开一段。
- 除了上表的两种触发方式，别的话我不会接——既不回复，也不会主动插话。

### 3. 命令手册

命令都由本地识别，位置不对就只是普通文字。几条通用规则：

- 命令**只在私聊与大区**解析；博客评论区不认（评论区里只有 `/help` 与 `/reset` 有效）。
- **一条消息里只能有一条命令**，且必须写在消息开头（大区里是去掉精确 @ 之后的开头）。
  命令后面紧跟着另一条命令时，我会回一句提示，请你分成两条消息发。
- 参数留空会返回**用法提示**，本地回复、不调模型。

#### 3.1 `/help` 与 `/reset`

| 命令 | 作用 |
|------|------|
| `/help` | 再看一遍我的能力、隐私与限制说明（**本地回复，不调用模型**） |
| `/reset` | 开始一段新对话，从头开始（旧的还在，别人仍可以接着旧的那段聊） |

这两条要求**整条消息就是命令**（前后不要带别的字），大小写不敏感。评论区里写
`@<机器人用户名> /help`，或直接回复我的评论写 `/help`、`/reset`，效果一样。
`/reset` 只作废短对话的上下文，**不等于删除长期记忆**（见 3.3）。

#### 3.2 五条能力命令

| 命令 | 查什么 | 前提 |
|------|--------|------|
| `/search <问题>` | 联网搜索（第三方 Exa） | 站长启用 MCP |
| `/zhihu <问题>` | 知乎站内内容 | 站长启用 |
| `/map <问题>` | 高德的地点、坐标与天气 | 站长启用 |
| `/wolfram <问题>` | Wolfram 计算或事实查询 | 站长启用 |
| `/kb <问题>` | 站长放在本机知识库里的 Markdown 资料 | 站长启用；默认只对指定的私聊用户开放 |

- 用法是命令加空格加问题；`/searching`、`/kbase` 这类写法不会触发。
- 这五条**只授权当前这一轮**：由模型判断本轮要不要真的去查，一次一轮；`/search` 默认最多五条摘要。
- 它们返回的都是**不可信的外部资料**，可能不准确或包含误导性文字；搜索只看摘要，不抓取网页全文。
- `/kb` **不联网**：只查站长放进知识库目录里的资料。没有命中我会直接说明，不会拿常识冒充资料，
  也不会因此转去联网；知识库有刷新周期，刚放进目录的文件可能要等一会儿才能检索到。
- 站长没启用 `/zhihu`、`/map`、`/wolfram` 时，我会回一句「暂不可用」；`/search` 与普通聊天不受影响。
- **评论区不支持这五条**，也不会因此调用搜索、地图或读取知识库。

#### 3.3 长期记忆：`/remember` 与 `/memory`（仅私聊）

**默认关闭，由站长按名单灰度开放**，所以要是有「别人能用、你不能用」，那不是坏掉了。
没被开通时，发这些命令只会收到一条「还在测试阶段」的固定提示，其它功能不受任何影响。开通后：

| 命令 | 作用 |
|------|------|
| `/remember <内容>` | 立刻整理并保存一条只属于你的私有记忆：我会把**实际保存的正文与条目 ID**回给你，没保存成功就直说 |
| `/memory status` | 看私有记忆与自动记忆是开还是关、私有条目数与公开条目数 |
| `/memory on` / `/memory off` | 开启或暂停在私聊回复里**参考**你的私有记忆；`off` 会一并关掉自动记忆（已有条目都保留） |
| `/memory auto on` / `/memory auto off` | 开关**自动记忆**：是否从你的私聊内容里自动整理条目（需站长的部署开关也打开） |
| `/memory list` | 列出你自己的私有条目 |
| `/memory list all_user`、`/memory list lobby` | 列出已生效的共同记忆（全站 / 大区） |
| `/memory list public` | 列出你已公开的条目 |
| `/memory public <UM-ID>` | 把一条私有记忆**公开**出去 |
| `/memory unpublic <UM-ID>` | 撤回它的公开副本；私人条目本身不动 |
| `/memory forget <UM-ID>` | 删除一条私有记忆 |
| `/memory clear` | 清空全部私有记忆 |

三类记忆：

- **共同记忆**（`all_user` 全站、`lobby` 大区）：所有人共享，管理员审核后才对所有人生效；
  大区里这两份都可能被参考，博客评论区只可能参考 `all_user`。
- **私有记忆**：每人一份，只在你自己的私聊里被参考；**大区与评论区永远不会用到它**。
- **你主动公开的个人条目**：从私有记忆里逐条公开出去的**快照**。

要看清这几点：

- **只在私聊**：在大区里发记忆命令，我只会回一句「记忆命令只在私聊里可用」；评论区不把它当命令。
- **自动记忆只拿你自己写的原文**，而且要你先开启；寒暄、一次性任务、临时指代都会被判为「不需要记」。
- **公开的适用范围**：大区与博客评论区里**出现或精确提到你**时，你公开的那几条才可能随那一轮请求
  一起发给第三方模型。触发来源是别人消息里的**完整用户名**（不必 @ 你）、博客与文章正文里的用户名、
  以及已经展开的公开剪贴板里的用户名；**只做精确匹配，不做模糊匹配**（`alice` 不会命中 `alice2`）。
  站点核对用户名时有限频，所以是「可能用到」，不是「一定用上」。
- **`/memory off` 不撤回公开条目**：它只暂停私聊里的参考；撤回要用 `/memory unpublic <UM-ID>`。
  `/memory forget` 与 `/memory clear` 会**先撤回公开副本、再删除私人条目**。
- **公开的是发布那一刻的快照**：之后改私人条目，公开的那一份不会跟着变。
- **`/reset` 不等于删除**：它只换一段新对话，已保存的条目还在，已经公开的仍然公开。
- 条目有上限（默认私有 32 条、公开 8 条）；到顶我会实话实说，绝不自动删除已有条目。
- 这些命令的**回复文案**由程序直出，不经过模型；但整理条目那一步会用到模型，所以内容同样会被
  转交给第三方（见第 7 节）。记忆读写即便出问题，也只影响这一次操作，聊天与评论不受影响。

站长指定的**记忆管理员**另有 `suggest`、`candidates`、`approve`、`reject`、`delete` 五条命令，
用于提出与审批共同记忆；普通账号调用只会收到一条权限提示。

### 4. 我会自动读什么

不用下命令，下面这些我会在需要时自己读：

- **你回复的那条消息**：它带的引用与正文会一起看。被引用的消息若是图片，我会去读**那张缩略图**
  （站点只提供缩略图，分辨率比原图低，图里的小字可能读不清）；取不到时我会记下「图片未提供」
  并照常回答，已删除的引用不会去读它的图。
- **正文里的 `[@<内容ID>]`**：按长度识别并展开——8 位是**云剪贴板**（读正文，单条最多 2000 字，
  超出部分不取）、9 位是**投票**（读标题、选项与票数）、10 位是**图床图片**（站长配了能看图的
  模型时我能看到图，否则只知道那里有一张图）。剪贴板与投票要么是公开内容、要么你自己是作者，
  否则读不到：那时我会写下「加载失败」，而不是装作那段不存在。写在**代码块或行内代码**里的
  `[@id]` 一律不展开；你回复的那条消息里若有引用，我会连它一起读。
- **你引用的博客**：我会去读它的**标题与正文**。正文超过 1000 字（站长配置）时只拿到标题，
  并会明确写下正文没给；取不到（已删除、暂时读不到）时同样只有标题。没被引用的博客我不会主动去看。
- **博客评论区的每一轮**：会读文章标题；正文不超过 1000 字时可能随本轮一起提供，超过则不提供。
  正文里写的 `[@id]` 同样会展开。
- **图片**：取决于站长有没有给我配能看图的模型。配了，你**这一轮**发的图会随本轮交给第三方模型
  （更早轮次里的图看不到）；没配，我会明确告诉你图没读到，请改用文字描述。评论区一轮最多几张图
  由站长定（默认 3 张），按「你的附件 → 评论正文里引用的图 → 文章正文里的图」的顺序给；
  **引用其他博客的附件我一直读不了**。评论区里**只发图、不写字**只能以「直接回复我的评论」
  的形式出现（第一次叫我必须 @，而 @ 需要文字）。
- **大区里最近的公开文字消息**：为了理解正在发生的讨论，我会在内存里保留最近 50 条大区文字消息、
  每条最多前 500 字。你叫我时，其中装得下的那部分会随这一轮一起发给第三方模型——**你没 @ 我的
  公开发言也可能被交给模型**。图片和拍一拍不进入这份内容；它只在内存里、只用一轮，用过即删除，
  重启也会丢失。这份内容是全大区共用的，所以别段的公开文字同样可能被读到。

### 5. 我做不到什么

- **普通聊天不联网，也不能运行代码。** 联网只有 `/search`（以及站长启用的那几条能力命令）
  这一条路，而且只授权当前一轮。
- **查不到站内数据**：别人的余额、鱼干流水、通知、申诉进度、资料，都要你自己去对应页面看。
- **不能替站方办事**：解禁、恢复内容、改角色、发邀请码、裁决申诉，一律请走 `/contact` 或 `/audit`。
- **长期记忆默认没有**：短对话的上下文只放在内存里，换一段对话就是重新开始，服务重启也会丢
  （去重与额度状态会保留）。
- 不确定的事我会直说，不会编。站内规则以页面为准，指南在 `/clipboard/guide`、
  `/image/guide`、`/vote/guide`、`/tool/cattca-guide`。

### 6. 为什么有时不回、有时很慢

| 现象 | 原因 |
|------|------|
| 大区里没 @ 我 | 设计如此：只回应精确 @，否则会把当天的额度烧光 |
| @ 了我，却像没接上文 | 没有回复链内的消息就会开一段新对话；想接上就回复这段里的消息再 @ 我 |
| 博客区 @ 了我却迟迟没反应 | 评论每 30 秒扫一次全站最近 100 条，通常半分钟到一分钟内开始处理；启用功能之前的旧评论、两次轮询之间新增超过 100 条的窗口外评论，可能漏失 |
| 博客区只是普通评论、或回复了别人的评论 | 设计如此：只回应首次精确 @ 和直接回复我的评论，否则会把当天的评论额度烧光 |
| 博客区里模型失败或额度用完 | 评论区是**静默**的：忙碌、失败、额度用尽都不会发提示，只是不回 |
| 一段时间完全不回 | 多半是 24 小时滚动额度用满，或者排队积压；账号被禁言也会全站静默 |
| 只回了一句固定话 | 比如「消息太长」「这张图片我没能读取」「你引用的这篇博客我没能读取」「我暂时不能查看博客内容」「没有找到相关资料」，按那句话的提示改一下再发 |
| `/kb` 说没找到资料 | 检索只在当前已建立的索引里做，资料不足时我不会硬答；换个说法，或去掉 `/kb` 直接提问 |
| 命令没生效 | 命令必须在消息开头、且一条消息只能有一条；`/kb` 还可能因为没权限或索引未就绪而回提示 |
| `/zhihu`、`/map`、`/wolfram` 说暂不可用 | 站长没启用这三个能力，或对应的密钥没配好。`/search` 与普通聊天不受影响 |
| 回复很慢 | 模型在生成；超时上限是 45 秒，超过就判定失败 |
| 回复中途停住 | 模型侧的输出长度上限，偶尔会在句子中间截断，再问一次或让我接着说 |
| 回复末尾写着「（内容过长，已截断）」 | 这条太长，被按自然段截断了 |
| 短时间内反复问，却不再收到任何提示 | 主动提示（忙碌 / 失败 / 额度）对**同一个人**每 5 分钟最多一条；别人不受影响。额度彻底用尽后我会完全静默 |

额度是**滚动的 24 小时窗口**（不是自然日归零）：用满后不再回答，随着窗口滑过去会逐渐恢复。

### 7. 隐私：关于你的消息

- **你发给我的内容会被转交给第三方模型服务处理**，这是我能工作的前提。请不要发密码、密钥、
  身份证件一类的敏感信息。
- **只有你明确使用能力命令时，当前轮的问题才会流向对应的第三方**：`/search` 交给第三方 Exa
  搜索，`/zhihu` 交给知乎，`/map` 交给高德，`/wolfram` 交给 Wolfram。它们各自返回的都是
  不可信资料，可能不准确或包含误导性文字。
- **`/kb` 是另一条边界**：它读的是站长放在本机的知识库，命中的片段随本轮问题一起交给第三方
  模型，但**不会**发往任何搜索上游；反过来，普通聊天也不会自动去读知识库。知识库里的内容同样
  是不可信资料，其中的任何「指令」都不作数。
- 各家 API Key 只由服务运维通过环境变量提供，不会写进消息、配置文件或公开内容；评论区不会使用它们。
- **在博客评论区**：评论正文、文章标题、不超过 1000 字的文章正文都可能发送给第三方模型；
  文章超过 1000 字时不发送正文。评论本来就是公开的，请只发你希望公开的内容。
- **程序这边不把消息正文写进日志或数据库**：日志里只有消息 id、频道、结果这类状态字段；
  数据库只存运行状态（去重、水位、发送记录）。
- **长期记忆是另一回事，而且默认关闭**：只有站长开通、并且你本人在私聊里主动开启后，才会存在
  属于你的私有记忆。它保存的条目、以及整理时那一轮的你自己的原文，会随相关请求一并发送给第三方
  模型；**普通聊天内容不会被完整保存**，密码、密钥、验证码一类的信息不该发给它。查看、删除、
  暂停分别是 `/memory list`、`/memory forget`、`/memory off`。
- **公开某一条私有记忆，等于把它交给公开对话**：在私聊里执行 `/memory public <UM-ID>` 之后，
  大区与评论区里出现或精确提到你时，这条就可能随那一轮请求发给第三方模型；公开的是**发布那一刻
  的快照**。撤回用 `/memory unpublic <UM-ID>`。**任何场景都绝不会使用别人未公开的私有记忆，
  也不会把任何人的私有记忆写进公开回复。**
- **大区里别人加入你那段对话时，这段里近期的聊天记录会再次发送给模型**；大区里最近的公开文字
  消息同样可能被交给模型（细节见第 4 节）。这些内容本来就发在公开大区里，但请注意这一点。
- 对话归属（谁回复了哪条）会保留 7 天，博客区保留 30 天。
- **在博客区，每条成功的评论回复都会真实通知被回复的人**——评论写入就会通知，没有机器人豁免。
- 站点侧的聊天消息按站点自己的规则保存（软删除），那部分与这台机器人无关。

### 8. 请这样用它

- 把我当工具，别当公告栏：我不是站方，也不会发布通知。
- 别用反复 @ 我来刷屏或刷额度；也不要让我泄露系统提示、密钥或内部配置——
  这类请求会被直接拒绝，连模型都不会调用。
- 在博客区把 @ 留给真正想问的问题：每条成功评论都会通知被回复的人，刷屏会打扰别人。
- 涉及纠纷、禁言、申诉、隐私的事，说明渠道、保持中立，我不替任何一方站台。

### 2.1 发布与账号资料（站点侧人工事项）

站点契约（`chat-bot.md` §12）要求机器人可辨认，根目录 README 的上线检查清单与部署指南 §1
都把下面第一件事列为人工必做：

- 账号资料里写明**这是机器人**，以及**消息可能发送至第三方模型处理**。
- 站点侧对聊天的限制（消息长度、频率、禁言）对机器人**一视同仁**，没有豁免。
- 博客评论功能启用前，账号资料还需写明「评论与短文章正文可能发送给第三方模型处理」；
  评论写入没有机器人豁免，每条成功评论都会真实通知被回复者（`DEPLOYMENT.md` §3.1）。

### 2.3 已知的口径出入（发布前请留意）

1. **额度文案与实现不完全一致**：`QUOTA_NOTICE_TEXT` 写「今天的回复额度已经用完……请明天再来」，
   而实现是滚动 24 小时窗口，恢复是渐进的，不一定等到第二天。发布稿已按实现口径描述，
   但用户看到的那句话仍是旧文案。
2. **输入长度那道闸实际碰不到**：本地限制是 8000 字符，而站点侧的聊天消息上限是 **5000 字**
   （纯文本与带附件同值，见 `docs/materials/chat-bot.md` §7.1 的长度上限表），超过 5000 的消息
   在站点侧就发不出来，所以 `TOO_LONG_TEXT` 在正常使用中不会出现。真正会遇到的是模型侧输出上限
   导致的截断。
3. **模型侧截断没有任何提示**：`model.max_output_tokens`（默认 600）触发的截断不会追加说明，
   回复会在句子中间停住；只有本地那层 5000 字符的截断会写「（内容过长，已截断）」。
   嫌难看就调大 `max_output_tokens`，详见 `DEPLOYMENT.md` §15.1。
4. **评论区的"漏失窗口"是上游限制**：发现靠每 30 秒拉一次全站最近 100 条，两次轮询之间新增
   超过 100 条时窗口外评论无法恢复。发布稿已如实写"可能漏失"，没有承诺必达。
5. **评论区的额度文案**：聊天区的 `QUOTA_NOTICE_TEXT` 写「请明天再来」，实现是滚动 24 小时窗口；
   评论区额度用尽则完全静默，连这句话也没有。发布稿对两处都按实现口径描述。
6. **公开条目的命中还取决于站点的用户查询**：普通用户名、博客与文章正文、剪贴板里的用户名
   都要过一次 `GET /api/chat/users` 的精确核对（完整用户名、大小写敏感）。这个接口站点限频
   20 次/分钟，机器人自己节流到 15 次/分钟并做正/负缓存；限频、超时或响应形状认不出来时按
   「这个人对不上」处理（fail-closed），那一轮就不会用到对应的公开条目。发布稿与 `/help` 都用
   「可能」描述这件事，没有承诺必中——本文件也不要写成「提到就一定用上」。
7. **自动提取的披露可能缺席（唯一一处「写了但没说」）**：站长的 `behavior.max_output_chars`
   紧到装不下「披露 + 一个回答字符 + 截断后缀」时，这一轮的回答照常完整发送，但末尾**不会**有
   「（已新增私有记忆 UM-……）」那句。记忆确实写进去了，用户可以在私聊里用 `/memory list` 看到
   并删除它；服务端会记一条 `reason=disclosure_no_room` 的日志（D-77）。因此**发布稿不要把
   自动记忆写成「每次保存都会告诉你」**：正常情况下会在回答末尾说明（这是设计的要求），但这是
   一条有例外的承诺。部署侧给这两个上限留余量即可让它在默认配置下永远不出现。

### 2.4 改这份文档时注意

- 第一部分的用词要与 `texts.py` 的固定文案对得上（`/help`、用法提示、不支持媒体、超长、
  忙碌、失败、额度用尽、记忆命令那一组），否则用户在聊天里看到的话和公告对不上。博客区的对应
  文案由 `texts.comment_help_text()` 拼装（首次 @、直接回复、文章正文上限、图片开关、真实
  通知、重启丢短期上下文、读不到被引用的博客）；站长开启长期记忆后才多出那一句披露 ——
  它必须同时点出 `all_user` 共同记忆与参与者**主动公开的个人条目**，只说前者在公开投影上线后
  就是假话（§36、§50.2）。聊天侧的 `/help` 里，公开个人记忆那一段按公开设计 §17.2 **逐字**
  出现（`texts._HELP_MEMORY_PUBLIC` 的第一句是合同的原文），改写它等于改合同；关闭记忆时
  这一版文案与上线前逐字节相同，所以本文件里「默认没有」的措辞也要与那一份对得上。
  **文案里的每个数字都来自配置**（`article_max_chars`、
  `quoted_blog_max_chars`），本文件写死数字的地方要与配置默认值一致。
- 任何一条行为改了，先回 `docs/design/INTERFACES.md` 与 `docs/design/DESIGN_DECISIONS.md` 确认是不是有意为之，
  再改这里。裁决记录里的 D-1、D-18、D-19 都与本文件的「为什么有时不回」一节直接相关。
