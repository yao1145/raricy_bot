# 我记住了：长期记忆开始内测

> 以前，换一段对话，我们就是重新认识。现在，我可以试着记住一点**你亲口让我记**的事。
> 但这还是个内测功能：默认没有，由站长按名单逐步开放。请先读第一节，再用第二节往后。

---

## 一、先说清楚：默认没有，按名单开放

长期记忆是**内测中的可选项，默认关闭**。所以你可能会看到「别人能用、我不能用」——那不是坏掉了。

- **还没有开通**：在私聊里发这些命令，我只会回一句
  「长期记忆还在测试阶段，当前账号还没有使用权限。普通聊天和其它功能不受影响。」
  除此之外一切照旧，聊天、搜索、评论区都不受任何影响。
- **已经开通**：下面这些命令都能用，全部**只在私聊里生效**。

大区是公开对话，在那里发记忆命令，我只会回一句「记忆命令只在私聊里可用，请在私聊中管理记忆」，不会读写任何记忆；博客评论区也不会把 `/remember` 这类文本当成命令。换句话说：**记忆的读写都发生在私聊；公开场合只会「参考」共同记忆与你自己公开过的条目，绝不动你没有公开的私有记忆。**

## 二、三种记忆，一眼分清

- **私有记忆**——只属于你。它只在你和我的私聊里被参考，别人看不到、也用不到；你可以随时查看、纠正、删除。
- **共同记忆**——所有人共享。分「全站」与「大区」两份，由管理员审核后才生效，内容对使用者公开：大区里我会参考这两份，博客评论区只可能参考全站那一份。
- **你公开的个人条目**——从你的私有记忆里挑出来、由你**逐条**公开的一份快照。它只在大区与博客评论里、且**只有当那段公开对话确实和你有关**时才会被参考（细则见第五节）。公开与否完全由你决定，不公开的条目一切照旧。

一条底线：**任何场景都不会使用别人未公开的私有记忆，也不会把你的私有记忆写进任何公开回复。**

## 三、命令（私聊里用）

| 命令 | 作用 |
|------|------|
| `/remember <内容>` | 把这段内容整理成一条只属于你的记忆；我会把**实际保存的正文和条目 ID**回给你 |
| `/memory list` | 查看你的私有条目；`/memory list all_user` 或 `/memory list lobby` 看已生效的共同记忆 |
| `/memory public <UM-ID>` | 把某条私有记忆**公开**出去（细则在第五节）；确认里会回显这条的 ID 与正文 |
| `/memory unpublic <UM-ID>` | 撤回公开：公开对话里不再用它，私人条目本身不动 |
| `/memory list public` | 查看你已公开的条目 |
| `/memory forget <UM-ID>` | 删除一条私有记忆（如果它已公开，公开副本一并撤回） |
| `/memory clear` | 清空全部私有记忆（已公开的一并撤回） |
| `/memory on` / `/memory off` | 开启或暂停在私聊回复里**参考**你的私有记忆 |
| `/memory status` | 看两个开关的状态、私有条目数与公开条目数 |

四点要知道：

- **第一次 `/remember` 成功时会顺带打开私有记忆**，不用你再确认一次。
- `/memory off` 会**一并关掉**自动记忆，但**不会删除任何条目**；条目只能靠 `/memory forget` 或 `/memory clear` 删掉。
- **`/memory off` 不等于撤回公开**：它只暂停私聊里的参考，你此前公开过的条目仍然公开——那几条要用 `/memory unpublic <UM-ID>` 逐条撤回（或者用 `/memory forget` / `/memory clear` 连条目一起删掉）。
- **`/reset` 不等于删除记忆**：它只是开始一段新的短对话，已保存的条目还在，已经公开的条目也仍然公开。

还有一组**自动记忆**：开启后，我在私聊里会把你**自己写的**、有长期价值的话自动整理成条目；它需要站长和你**两边**都打开才生效，用 `/memory auto on` 与 `/memory auto off` 控制。不放心就让它关着——手动 `/remember` 一样好用。

## 四、三个范例

**范例一：让我记住一件事（私聊）**

> 你：`/remember 我不吃香菜，点餐建议尽量避开`

> 我：已新增私有记忆 UM-000001：用户不吃香菜，推荐菜品时应避开香菜。
> 用 `/memory forget UM-000001` 可以删除这一条；再发一次 `/remember` 可以纠正它的内容。

正文是我**整理过的**，不一定是你原话——但一定是**实际存下来的那一份**，原文照发给你看。首次保存时，我还会附一段说明：之后的内容可能被整理成私有记忆、只在本私聊使用、并可能随相关请求一并发送给第三方模型。

**范例二：几天后，它真的被用上了**

> 你：今晚吃点什么好？

> 我：你不吃香菜，那我按避开香菜来推荐：……

记忆是**默默生效**的，我不会每次都提它。想确认存了什么，随时查看：

> 你：`/memory list`
> 我：你的私有记忆，共 1 条：
> UM-000001：用户不吃香菜，推荐菜品时应避开香菜。
> 用 `/memory forget <UM-ID>` 可以删除其中一条；再发一次 `/remember` 可以纠正它的内容。

不想要了就删掉，删除**立即生效**：

> 你：`/memory forget UM-000001`
> 我：已删除私有记忆 UM-000001。

**范例三：把一条公开出去，用完再撤回（全部在私聊）**

> 你：`/memory public UM-000001`

> 我：已公开 UM-000001：用户不吃香菜，点餐时应避开香菜。
> 它现在是你主动公开的个人记忆：大区与博客评论里出现或精确提到你时，这一条可能随该轮请求一起发送给第三方模型。公开的是这一份快照，之后修改私人条目不会自动更新它。用 `/memory unpublic UM-000001` 可以撤回公开。

之后在大区或某篇博客的评论里，只要有人的消息**写出你的完整用户名**（不必 @ 你；博客与文章正文里、以及已经展开的公开剪贴板里出现你的用户名同样算），我可能就当轮用到这一条。不想让它继续公开时：

> 你：`/memory unpublic UM-000001`
> 我：已撤回 UM-000001：它不再用于公开请求，你的私人条目没有被改动。

撤回确认里**不会**再回显那条正文，而私人条目仍然好好地在 `/memory list` 里。

## 五、边界与隐私

- **普通聊天不会被完整保存。** 只有你主动 `/remember`，或者你开着自动记忆、且那句话确实有长期价值时，才会产生条目；寒暄、一次性任务都会被判为「不需要记」。
- **自动记忆只拿你自己写的原文**，不拿我的回答、搜索结果、知识库片段。
- 记忆**可能随相关请求一并发送给第三方模型**（和普通聊天同一条链路），所以别把密码、密钥、验证码这类内容交给它。
- 条目有上限（默认：私有 32 条、公开 8 条，每种共同记忆 64 条）。到顶我会实话实说，**绝不自动删除已有条目**。
- 这些命令的回复由程序直接给出，**不经过模型**；记忆读写即便出问题，也只影响这一次操作，聊天与评论区不受影响。

### 关于「公开」这一件事

- **公开与撤回都只在私聊里做**，大区里没有这个入口：`/memory public <UM-ID>` 与 `/memory unpublic <UM-ID>` 都是私聊命令。
- **只有你逐条公开过的条目才会进入公开对话**，而且**只有当那段对话确实和你有关**时才可能被用到：别人在消息里写出你的完整用户名（@ 一下当然也算，但**不必** @）、博客与文章正文里出现你的用户名、已经展开的公开剪贴板里出现你的用户名，都可能触发。
- **只按完整用户名精确匹配，不做模糊匹配。** 我叫 `alice` 的时候，别人说 `alice2`、`myalice` 都不会把我认成你；大小写也要对得上。站点在核对用户名时会做限频，因此命中是「可能用到」，不是「一定用上」。
- **公开的是发布那一刻的快照。** 你之后改私人条目、删掉它，公开的那一份都不会跟着变——所以别把「改了私人条目」当成「公开的内容也改了」。
- **撤回入口只有 `/memory unpublic <UM-ID>`**（或 `/memory forget` / `/memory clear`，它们会连条目一起处理）。**`/memory off` 不撤回公开条目**：它只暂停私聊里的参考，已经公开的仍然公开；**`/reset` 也不删除、不撤回**长期记忆，它只是换一段新的短对话。
- **未公开的私有记忆永远进不了公开请求**：大区与评论只会去读 `public/` 那份投影，你的私人文件在那两条路径上一次都不会被打开。公开条目也只在**当前这一轮**使用，不写进日志、不写进数据库、不进短期历史。

## 六、给记忆管理员（普通用户可跳过）

共同记忆要经过「起草 → 审批」两步才生效。这五条命令只对站长指定的**记忆管理员**开放——管理员必须**先通过开放门、且名字在管理名单里**（按名单开放时，就是两个名单都必须在），且同样**只能在私聊**操作：

| 命令 | 作用 |
|------|------|
| `/memory suggest <all_user\|lobby> <内容>` | 让我起草一条候选；它**不会立刻生效** |
| `/memory candidates` | 列出全部待批准候选 |
| `/memory approve <MC-ID>` | 批准：候选移入生效区，**对所有使用者生效** |
| `/memory reject <MC-ID>` | 丢弃候选；已生效的共同记忆不受影响 |
| `/memory delete <GM-…>` | 删除一条已生效的共同记忆 |

两个要点：候选在批准前**不生效、也不会进入任何模型请求**（共同记忆人人可见，未审内容一个 token 都不外发）；`approve` **不调用模型**，只是把候选原子地移入生效区。若候选起草之后，目标条目又被别处改动过，批准会被拒绝而不是覆盖新内容——重新起草一次即可。
