# 知识库的来源与刷新

`knowledge/网站信息/` 是根据站方公开指南、公开页面行为和本机器人使用手册重写的问答资料，供 `/kb` 检索。每个 `##` 是一个可以独立回答的问题，正文保留操作步骤、权限、限额、公开范围和常见故障。版本与溯源只记在本文件，不写进检索正文。

配置和刷新行为见 [EXA_POOL_AND_KB.md](../usage/EXA_POOL_AND_KB.md) 与 [INTERFACES.md](../design/INTERFACES.md) §23。按本地、服务器与 GitHub 同步的要求，公开的 `knowledge/网站信息/` 纳入版本控制；其他知识库目录仍被 Git 忽略。网站资料和本文件随同一提交同步，部署后再确认运行中的索引刷新。

### 五类日常指南的核对记录

`docs/bot/` 用来提炼公开的用户操作规则，不把 HTTP 请求示例、认证凭据、接口 DTO、内部字段或运维命令搬入知识库。页面按钮、入口和角色门槛以同一提交的实际页面与鉴权代码核对。

- 鱼干余额、流水、市场与只读凭据页面只要求登录；签到另需 Core、有效文章和未禁言。同步修订站点概览中把全部鱼干功能归为 Core 的旧说法。依据为鱼干页面、市场鉴权和签到服务。
- 站方 `comment-bot.md` §8 首段仍写“没有 @ 提及”，但同篇已列“评论提及”通知；当前评论输入区提供提及选择器，评论服务明确发送评论提及通知，`docs/architecture.md` §6.7 也有说明。知识条目采用当前已实现的回复与提及规则，未修改站方原文。
- 账号接口支持四类通知偏好，但当前设置页面没有它们的独立开关。知识条目说明偏好作用，并指向站长核对，不虚构页面按钮。
- 网页普通转账未提交可复用的幂等键；网络结果不确定时先查流水，不能直接把第二次点击视为原操作重试。转账与投喂的用户指南只写这一行为，不收录服务集成示例。

## 重写规则

一篇指南对应一篇主题文件，一个独立问题对应一个 H2。标题使用读者会问的词，例如"音频大小"、"头像框租金"、"引用上限"；每条正文可以单独检索使用，避免依赖前后文。单条问答不超过当前 `chunk_chars=2400` 的分块上限。

保留站方给出的数字、单位、按钮名、页面路径、公开范围和失败表现。代码示例使用完整命令块；上游 `input text` 示例中缺少的 `/>` 按基本语法补齐，提示正文放在命令块之外。

省略密钥、Cookie、IP 字面量、宿主目录、数据库和部署拓扑、内部组件、运维命令和源码路径。故事作品元数据与 Cattca 命令属于作者需要使用的格式，可作为代码示例保留。

本次按用户要求整目录替换，旧 ATÅMAS 和联机棋类隐藏资料一并移除，不再保留于知识库。历史来源可追溯本文件的 Git 历史，不将已下线内容继续参与检索。

## 更新与验证

1. 从公开仓库取得当前提交，记录 SHA、时间和许可；从该提交读取指南，而非直接使用可能含未提交修改的工作区。
2. 对照 `docs/guide/` 和本表，逐篇核对新增、删除和修改；按用户侧用途重写，更新受影响的限额、权限、按钮和路径。
3. 使用机器人实际 `build_snapshot` 和 `KnowledgeIndex` 检查 UTF-8、标题结构、问答长度、跳过文件与代表性问题的命中。
4. 逐篇复核可公开性，确认没有凭据、隐私、运维配置和无权交给模型的材料。命中片段会展示给提问者并发送给模型。
5. 上传完整新版网站信息目录，校验文件哈希；保持挂载根目录不变，让现有知识库刷新加载。用 `kb.ready` 的文件 / 分块数量和服务器上的检索确认生效。

知识库内容检查不能代替机器人运行健康检查；上传后另查现有服务状态和健康端点。服务器访问策略以当前配置为准，本次内容更新不调整可用频道或用户范围。
