## 重写规则

一篇指南对应一篇主题文件，一个独立问题对应一个 H2。标题使用读者会问的词，例如"音频大小"、"头像框租金"、"引用上限"；每条正文可以单独检索使用，避免依赖前后文。单条问答不超过当前 `chunk_chars=2400` 的分块上限。

保留站方给出的数字、单位、按钮名、页面路径、公开范围和失败表现。代码示例使用完整命令块；上游 `input text` 示例中缺少的 `/>` 按基本语法补齐，提示正文放在命令块之外。

省略密钥、Cookie、IP 字面量、宿主目录、数据库和部署拓扑、内部组件、运维命令和源码路径。故事作品元数据与 Cattca 命令属于作者需要使用的格式，可作为代码示例保留。

本次按用户要求整目录替换，旧 ATÅMAS 和联机棋类隐藏资料一并移除，不再保留于知识库。历史来源可追溯本文件的 Git 历史，不将已下线内容继续参与检索。

## 更新与验证

1. 从公开仓库取得当前提交，记录 SHA、时间和许可；从该提交读取指南，而非直接使用可能含未提交修改的工作区。
2. 对照 `docs/guide/` 和本表，逐篇核对新增、删除和修改；按用户侧用途重写，更新受影响的限额、权限、按钮和路径。
3. 使用机器人实际 `build_snapshot` 和 `KnowledgeIndex` 检查 UTF-8、标题结构、问答长度、跳过文件与代表性问题的命中。
4. 逐篇复核可公开性，确认没有凭据、隐私、运维配置和无权交给模型的材料。命中片段会展示给提问者并发送给模型。
5. 上传完整新版网站信息目录，校验文件哈希；保持挂载根目录不变，让现有知识库刷新加载。用 `kb.ready` 的文件 / 分块数量和服务器上的检索确认生效。

知识库内容检查不能代替机器人运行健康检查；上传后另查现有服务状态和健康端点。服务器访问策略以当前配置为准，本次内容更新不调整可用频道或用户范围。
