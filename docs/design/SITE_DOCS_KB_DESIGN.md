## 1. 目标与非目标

**目标**：让站内用户用日常问法问 `/kb` 时，机器人能拿站方对外文档里的事实作答 ——
某个功能怎么用、有哪些限制、联机对局怎么判胜负。

**非目标**（明确的边界，避免越做越大）：

- 不改 `src/raricy_bot/` 下任何代码，不改 `config.yaml` / `config.example.yaml`。
- 不引入依赖，不写抓取或同步脚本。上游更新靠本文 §9 的留痕文件人工跟进。
- 不逐字搬运上游正文。本次是**重写为问答**，事实照抄、句式重写（§4、§6）。
- 不收录开发与运维文档（`deploy.md`、`cli.md`、`oauth.md`、`chat-bot.md`、`comment-bot.md`、
  `frontend-styles.md`、`instance-restore.md`、`architecture.md` 原文）。`architecture.md` 只作为
  §8 站点概览的取材之一。
- 不收录 `raricy.com-ng` 仓库的迁移文档。该仓库是迁移暂存处，`docs/` 已于 2026-07-16 冻结，
  其中的《全站限额与频控汇总》在迁移完成后没有跟随站点更新，收录它等于把过时数字当权威。
  限额以现行 `docs/guide/*` 各篇的「限制一览」与站点页面为准。

## 4. 删减规则

上游这些文档是**给站内页面渲染**的，也夹着面向维护者的实现说明。重写时按三类处置：

**保留并照抄**：用户能观察到的一切事实 —— 限额与频控数字、字数与数量上限、页面路径、
按钮名称、判定规则、公开/私密语义、常见问题里的结论。数字必须逐字照抄，不得换算、不得取整、
不得"约"。

**删除**：源码级实现细节 —— 文件路径与文件名、组件名与类名、状态对象字段、渲染与缓存实现、
数据管道、路由表、数据库与部署、迁移史、风险清单。例：`atamas-game.md` 的「技术架构」
（`Atamas.tsx`、`engine.ts`、`state.elements[]`、`requestAnimationFrame`）与「路由」里的源文件
路径全部删除；但同一节的「不需要登录即可游玩」「状态仅存浏览器内存，刷新页面即丢失」属于
用户可观察事实，必须保留。

**蒸馏**：实现章节里混着用户可观察行为时，留行为、去实现。典型是
`内容引用语法指南.md` §五「技术实现简述」—— `ContentRefProcessor`、`DOMPurify`、`Map` 缓存、
并行请求全部删除，但下面这些要留下并问答化：

- 一篇文章最多替换 50 处引用（三种类型合计），超出部分原样保留 `[@id]` 字面量。
- 评论与聊天不走博客那套管道：那里的投票**不展开**；手写 `<img>` 标签在博客正文里允许、
  在评论和聊天里不允许（防跟踪像素）。
- 图片在评论与聊天里只有站内图床这一种形态能出现。

**不收录**：与站点使用无关的内容，以及任何密钥、Cookie、内网地址、个人信息。本批文档为
公开仓库的对外文档，逐篇复核后确认无此类内容（验收 §10.3 再核一遍）。

分类名与相对路径**会直接交给模型**（`分类: <一级目录>`、`来源: <相对路径>`，见
`kb/service.py`），因此两者都必须能公开、且对用户有意义 —— 上面每个名字都可以当作回答的来源
念出来。文件名用中文主题名而非上游的 `*-online.md` / `*-guide.md`，因为 `来源:` 会连着问句
一起出现在答案里。

根目录不放文件：根下文件会被归入保留分类 `_root`，该字符串对用户没有意义。

## 6. 问答写法

**粒度**：一篇上游文档 → 一个目标文件；一个独立问题 → 一个 `##` 标题；标题即用户会问的那句话。
文件首行 H1 是主题名（`# 投票箱`），它是该文档的标题（参与检索加权）。

**单条约束**（来自 KB 的实际机制，不是风格偏好）：

| 约束 | 依据 | 写法要求 |
|---|---|---|
| 标题变化即切块 | `kb/loader.py` `_pack`：标题变化、空行边界、超长都切块 | 一条问答自成一块，检索命中就是一个完整答案 |
| 单块上限 `chunk_chars`（默认 2400） | 超长按字符硬切，会在句中断开 | 一条问答正文不超过 2400 字符；超了拆成两条 |
| 同一文件最多返回 2 段 | `INTERFACES.md` §23.5 | 一个主题不要塞入互相独立的问题簇，否则一个问题会挤掉同主题的另一段 |
| 检索是词法 BM25，中文按**单字 + 相邻双字** | `kb/index.py` `_tokenize` | 问题标题里必须出现用户的词面（「投票」「创建」「限额」「禁手」），不能只写「创建流程」这类抽象标题 |
| 分类 +1.5 / 路径 +1.0 / 标题 +0.8 / 标题路径 +0.6 | `kb/index.py` 权重 | 关键名词同时出现在标题路径与正文里，命中更稳 |
| 最高分低于 0.5 视为无命中 | `MIN_SCORE` | 同义改写要覆盖常见叫法（如「剪贴板」与「云剪贴板」） |

**正文形态**：直接给结论，再给依据；表格与数字照抄上游；命令与代码块原样保留（围栏内不会被
空行拆开）。不写「如上文所述」这类需要前后文的指代 —— 每一块都可能被单独取出来给模型。

**数量**：以覆盖上游事实为准。设计时预估 120–160 条，按「全覆盖上游事实」实做下来是 **220 条**
—— 上游每篇的「常见问题」章节几乎每条都值得独立成条。分档不设硬指标，只要求 §10.1 对账表逐节闭合。

## 7. 五款联机棋类：合并通用部分

上游这 5 篇的 H2 骨架逐字相同：`简介 / 开始之前 / 开一局 / 对局 / 掉线与判胜 / 观战 / 再来一局 /
房间有效期 / 常见问题`。逐篇问答化会产生 5 份同义条目，既浪费检索预算，又让「怎么开房」这类问题
在 5 个文件里各命中一次。

处置：**通用部分合并进 `联机对战/联机对战通用.md`** —— 开房与邀请、进入对局、掉线与判胜、
观战、再来一局、房间有效期、前置条件（登录与 Core）、棋盘与操作方式中跨棋种一致的部分。

**每款游戏只留自己的东西**：

| 文件 | 保留的游戏特有事实 |
|---|---|
| 五子棋 | 三三 / 四四 / 长连等先手禁手规则及其判定 |
| 井字棋 | 三子连线、平局、先手顺序 |
| 中国象棋 | 红先、马蹩腿 / 象塞眼 / 炮翻山、困毙判负、长将判负 |
| 国际象棋 | 易位、吃过路兵、升变、逼和与五十回合 |
| 国际跳棋 | 吃子强制、最大吃子、王的飞吃、连吃中途不升变 |

各款文件仍需与该棋种相关的胜负判定与常见问题；跨棋种一致的内容只在通用篇里出现一次，
不重复。搜索结果里同一主题最多返回 2 段，通用篇 + 棋种篇的组合正好落在预算内。

## 8. 站点概览

一篇 `站点概览/聪明山.md`，取材三处：站点首页文案（最权威的对外口径）、仓库 `README.md` 的
一句话定位、`architecture.md` 的功能子系统清单。收录：

- 站点名与定位：聪明山（Raricy.com），个人站点，栏目为故事/小说、玩具（游戏）、博客/文章、工具，
  另有剪贴板、图床、投票、日志。
- 各栏目是做什么的，以及进各栏目的路径。
- 角色与门槛：邀请码认证后为 Core，部分功能（如投票箱）需要 Core 及以上。
- 限额在哪看：指向对应功能篇的「限制一览」，不在概览里另抄一份数字（避免两处数字打架）。

不收录：技术栈、进程拓扑、目录布局、数据流、迁移史、风险与已知限制。

## 9. 留痕

内容是全量重写，无法自动跟随上游，因此需要一条人工可核的线：新增
`docs/materials/SITE_DOCS_SOURCE.md`，记录：

- 来源仓库 URL、许可、锁定的提交 SHA 与提交时间；
- 复现用的稀疏克隆命令（§2）；
- 一张对照表：每个 `knowledge/` 文件对应上游哪几篇、覆盖到哪些章节，以及本篇内容是基于
  哪个 SHA 写的；
- 上游更新时的复核做法：重新克隆 → 比对 SHA → 只对变化的上游文件重跑对应问答 → 更新 SHA。

该文件放在 `materials/`（站方与对外资料的入口），不放在 `knowledge/` 下 —— 知识库根下的
任何 `.md` 都会被收录并在回答里当作来源露出。

## 10. 验收

**10.1 逐篇对账**：每个目标文件配一张对账表（上游章节 → KB 条目），逐节确认无遗漏；
所有数字（限额、字数、数量、ID 位数、路径、按钮名）与锁定的 SHA 逐项比对，一个不放过。
这是「全覆盖上游事实」的唯一可验证口径。

**10.2 检索冒烟**：用 KB 自己的索引对一组真实问句跑一遍，确认首条命中落在预期的文件与条目上。
问句至少覆盖每个分类，例如：`投票怎么创建`、`图片最大能传多大`、`引用语法怎么写`、
`五子棋禁手是什么`、`怎么开一局象棋`、`Cattca 的 random 怎么用`、`这个网站是干什么的`、
`剪贴板的正文能写多长`。冒烟脚本是本地一次性工具，不入库。

**10.3 公开性复核**：逐个确认分类名、文件名、正文与来源路径里没有密钥、Cookie、内网地址、
个人信息，也没有把上游标为「面向开发」的实现细节带进来。KB 会把命中片段交给第三方模型并
展示给提问者（`usage/EXA_POOL_AND_KB.md` §2.2 的前置门禁），这一步不能跳。

**10.4 结构自检**：`knowledge/` 每个文件的 H1 唯一、无 front matter、全部 UTF-8、
无超过 2400 字符的单条问答、根目录无散落文件。
